# python-fundamentals

Core Python language mechanics — generators, `yield`, context managers, decorators, scoping, and
other execution-model concepts that come up while reading or reviewing real project code.

|---|---|---|---|
| 2026-09-17 | EWM-App | [`response.raise_for_status()` in `login_cookie()`](SESSION-2026-09-17-EWM-App-response-raise-for-status.md) | Concept note, not a bug — question arose reading `login_cookie()` in `rain_crawler.py`. Explains that `requests.post()`/`.get()` never auto-raises on HTTP 4xx/5xx status codes (only connection-level failures like DNS/timeout raise before a `Response` exists), what `raise_for_status()` checks and raises (`requests.HTTPError`), the alternative `response.ok` boolean style, and why raising here lets the caller `crawl_day()`'s `try/except` log the real cause (e.g. HTTP 401) instead of a vaguer "no sid cookie" `RuntimeError`. No code changed. |
| 2026-09-17 | EWM-App | [Chunked file hashing with `iter(callable, sentinel)`](SESSION-2026-09-17-EWM-App-chunked-file-hashing-iter-sentinel.md) | Concept note, not a bug — question arose reading `_sha256_of()` in `swmm_model_import_service.py`. Explains the two-argument `iter(function, sentinel)` form, why `lambda: fh.read(1 << 20)` defers the call instead of invoking `.read()` once immediately, `b""` vs `""` as EOF sentinel, why `"rb"` mode is required for correct hashing, and why chunked reads avoid loading a large `.inp` file fully into RAM. No code changed. |
| 2026-09-16 | EWM-App | [`dataclasses.field(default_factory=list)` — tránh mutable default dùng chung](SESSION-2026-09-16-EWM-App-dataclass-mutable-default-field-factory.md) | Concept note, not a bug session — question arose while reading a SWMM network import dataclass (`junctions: list[JunctionRecord] = field(default_factory=list)`). Explains why `x: list = []` as a class/function default is created only once at definition time and shared across all instances/calls, why `dataclass` actively raises `ValueError` for mutable defaults (unlike plain functions, which silently allow the bug), and why `default_factory` must be a zero-argument callable invoked fresh per instance. No code changed. |
| 2026-09-15 | EWM-App | [Understanding `@contextmanager` / `yield` / singleton in `shared_connection.py`](SESSION-2026-09-15-EWM-App-context-manager-yield-teaching.md) | Not a bug — a 10-round conceptual Q&A during a Phase 2 PR review where the user (Junior Developer Mode) got stuck on `get_shared_session()`'s `@contextmanager`/`yield` pattern and the `_ensure_engine()` singleton. Built up understanding layer by layer: singleton pattern via `global` + module-level `None` check, why `with` on a raw SQLAlchemy `Session` isn't enough (`Session.__exit__` only closes, never commits/rolls back), what `@contextmanager` actually transforms (whole function, not just the `yield` line), the `__enter__`/`__exit__` protocol from scratch, why `next()` is called exactly twice on the generator, and a final mix-up between a variable's name and the value it references. Closed the gap with an actually-executed demo script (`FakeSession` class) proving the enter/body/exit ordering for both success and exception paths — hit a real `UnicodeEncodeError` from Windows cp1252 console encoding on the first run, fixed with `PYTHONUTF8=1`. No production code changed. |
