# Learning Archive

Central archive of learning reports across every project. Each entry records a real session: what
broke, why, and what fixed it. Newest first.

Reports are written by the `learning-logger` subagent at the end of a working session, mirrored here
from each project's own `docs/learn-log/`. Organised by **category — what the lesson is about — not
by project**: a Docker PATH bug in one repo and the same bug in another belong side by side. See
[how this works](#how-this-works) below.

## How this works

1. **Subagent `learning-logger`** (`~/.claude/agents/learning-logger.md`) writes the report.
2. **Stop hook** (`~/.claude/hooks/learning-log-on-stop.cjs`) detects a session that changed code
   and asks Claude to invoke that subagent before the session ends.
3. Each report is written to `<repo>/docs/learn-log/SESSION-<date>-<slug>.md`, then mirrored to
   `E:\Learning\<category>\SESSION-<date>-<project>-<slug>.md` and indexed here. The category is

Reports follow the 9-section template established in EWATER
(`docs/learn-log/_TEMPLATE.md`): requirement recap → implementation → remember card → code changes
in detail → how to find it again → concepts introduced → **where it got stuck** → verify → gotchas.

Section 7 ("where it got stuck") is the point of the whole exercise: symptom → cause → fix,
including the false leads, because ruling a suspect out teaches more than the final patch does.
